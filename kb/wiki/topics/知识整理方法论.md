> 用奥卡姆剃刀指导知识整理：只收录必要知识，只创建必要页面，只保留必要规则。

## 核心原则

1. **如无必要，勿增页面**——每个页面必须能独立存在、能被引用、能被检索到。模板里的示例链接不算真正的链接。
2. **防患未然优于事后修剪**——在创建新规则/新分类/新模板之前，先问「去掉它会怎样」。一旦建了，就会有人依赖它。
3. **简单方案优先**——能用 [[index.md]] 导航就不用分类目录，能用一个页面说清就不用两个。
4. **专注 = 说不**——不收录的文章和拒绝的复杂度，比收录的内容更能定义知识库质量。

## 当前结构

```
kb/
├── raw/       ← 原始资料，只读
├── wiki/      ← 结构化知识
│   ├── index.md
│   ├── topics/   ← 主题综合页
│   └── atoms/    ← 原子概念（一页一概念）
├── CLAUDE.md  ← 知识库规则（从简）
└── AGENTS.md  ← AI 操作规范（从简）
```

## 收录检视（每次收录前自问）

- 这个概念值得成为一个独立页面吗？→ 不足 200 字的内容不建独立页
- 这个页面能被其他页面引用吗？→ 孤立页面 = 不必要的实体
- 这个分类真的必要吗？→ 分类少于 3 个页面就合并

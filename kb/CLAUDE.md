# 个人 AI 知识库规则

> 预测驱动 + 奥卡姆剃刀：知识库的目的是建立可预测的模型，而非堆积信息。任何模型都是对现实的简化——不存在"完整"的知识页，只存在"有用"的知识页。

## 目录结构

```
kb/
├── raw/            ← 原始资料。只读，源头真相（经验锚点）。
├── wiki/           ← AI 维护的结构化知识。
│   ├── index.md    ← 总索引。每次收录后更新。
│   ├── topics/     ← 主题页。综合多个概念，连成网络。
│   ├── atoms/      ← 原子概念。一页一概念，可独立引用。
│   └── course-progress.md ← 课程收录进度追踪。
└── CLAUDE.md       ← 你正在读的。
```

## 方法论基础（渐构·世界模型）

### 核心原则
- **预测驱动**：建每个页面的目的，是让你能推演未见过的情况。问自己——"看了这页，我能预测什么？"
- **经验→模型**：raw/ 是经验（直接类比），atoms/ 是模型（抽象推演），topics/ 是两者的连接器
- **无穷现实**：任何模型都是简化。不追求"完整"，只追求"有用"
- **适用边界**：每个概念只在特定条件下成立。不标边界的概念是伪知识

### 概念五组（收录分类工具）
1. **对象概念** — 指代存在物（如"生命""知识库"）
2. **属性概念** — 指代特征/状态（如"抽象""具体"）
3. **关系概念** — 指代联系（如"因果""层级""代理"）
4. **操作概念** — 指代动作/过程（如"预测""学习"）
5. **情境概念** — 指代条件/场景（如"教育环境""原始社会"）

### 抽象层级
每个概念标注层级：**底层**（直接感知）→ **中层**（模式归纳）→ **高层**（元认知）

## 学习辅助模式（渐构分析驱动）

当用户说"学习/复习/检验/帮我理解"时，启动此模式。

### 判联诊断（3 步排查）
用户遇到学习困难时，三步定位问题：
1. **判别诊断**：用户能判断什么情况该用什么知识吗？→ 不能 → 对象层丢失，需补判别模型
2. **联结诊断**：用户能用已有知识推演新情况吗？→ 不能 → 判联错配或模型未建构
3. **记忆诊断**：用户能重现已学内容但无法应用于新情况吗？→ 能 → 机械记忆，需从"背"转"学"

### 个性化学习路径
基于诊断结果生成学习方案：
1. 明确输入输出：这个知识"适用于什么范围？能推测出什么？"
2. 拆解任务：需要建构哪些判别模型？哪些联结模型？
3. 推荐材料：知识库中哪些 atoms/ 是判别模型，哪些是联结模型？
4. 推荐方式：创验学习（自己推导验证）还是继承学习（重建他人模型）？

### 反遗忘检查（每页知识附带自检问题）
创建每个概念页时，自动生成：
- "如果你忘了这页，你能从哪些已知概念推导出它？"（防止记言代学）
- "你能举出一个这页知识不适用的情况吗？"（防止知识坍缩）

## 五个操作（五步流水线）

### Step 1: 经验采集 (Experience Collection)
1. 通读资料，提炼核心主张、关键概念、论证链条
2. 按主题模块聚合（非逐篇），保留因果链，不断章取义
3. 输出到 raw/，每篇不超过 200 行。超则拆分
4. 检查：每个主张可追溯到源，论证链完整

### Step 2: 概念建模 (Concept Modeling)
1. 从 raw 中提取可独立存在的概念 → atoms/
2. 每个概念分类：五组概念之一 + 抽象层级（底层/中层/高层）
3. 每页 < 200 字，一个概念
4. ⚠️ 奥卡姆剃刀检视：能被引用吗？够独立吗？过度拆分了吗？
5. 检查：脱离上下文能独立理解吗？类型和层级标注了吗？

### Step 3: 判联整合 (Judgment-Link Integration)
1. 将多个概念连成框架 → topics/
2. 标注判联关系类型：因果 / 层级 / 类比 / 对立 / 代理
3. 检测与已有内容的矛盾 → 标记 `> ⚠️ 矛盾：`
4. 更新 index.md
5. 检查：每个 topic 是否综合了 ≥3 个 atom？判联关系是否清晰？

### Step 4: 适用校验 (Applicability Check)
1. 逐页检查——每个方法论概念标注 **适用边界**（什么条件下成立/不成立）
2. 至少找出一个反例或边界情况
3. 检测"脱离现实"风险：纯抽象推演、无 raw/ 经验锚点的页面 → 补充锚点
4. 检查：每个方法论 atom 是否回答了"何时不适用"？

### Step 5: 规则内化 (Rule Internalization)
1. 将可操作的方法论部分嵌入 CLAUDE.md / AGENTS.md 作为内置规则
2. 不可操作的理论保留为 atoms/ 知识页
3. 每条新规则必须：具体到操作动作、有自检标准、与旧规则无冲突
4. 运行健康检查：矛盾扫描、孤立页检测、过时标记

## 写作规范

- 首页：`> 一句话摘要`
- 概念页额外标注类型和层级
- 链接：`[[页面名]]`
- 矛盾：`> ⚠️ 矛盾：`
- 过时：`> ⚠️ 过时：`
- 待办：`- [ ] 待验证项`

## 不要做

- 不改 raw/ 下的文件
- 不建空页面
- 不删内容（标记即可）
- 不一次超 10 页（分批）
- 不建无适用边界的空泛断言
- 不建无 raw/ 锚点的纯抽象页

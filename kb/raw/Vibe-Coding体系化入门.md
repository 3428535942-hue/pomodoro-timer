## 第零节：课程介绍 — Vibe Coding 是什么

Vibe Coding 翻译为"氛围编程"或"沉浸式编程"，由 OpenAI 的 Andrej Karpathy 提出。

核心定义：使用大白话向 AI 描述需求、目标和感觉，由 AI 自动生成可执行的代码来完成任务。用户关注"做什么"和"为什么做"，将"怎么做"交给 AI。

本质：一场高质量的"人机对话"。用户相当于 AI 的产品经理——动嘴提需求，AI 动手写代码。沟通越顺畅，产出代码质量越高。

### 目标用户（谁都能玩）

- 学生：整理课件、作业，自动重命名和归类
- 打工人：从微信/支付宝账单导出数据，自动计算分类支出
- 宝妈宝爸：记录宝宝辅食、生成周报
- 自媒体：批量修改图片尺寸、添加视频水印
- 学术：从几百篇文献中提取包含特定关键词的句子

### 为什么要学 Vibe Coding

1. 上手极快：不需要苦啃语法，零基础一小时跑通第一个程序
2. 啥都能干：办公脚本、个人网站、小程序、小游戏
3. 大趋势：AI 编程已是职场标配
4. 方便搞钱：做小工具搞副业，试错成本极低

## 第二节：提示词怎么写

Prompt 是用户和 AI 沟通的桥梁，是 Vibe Coding 的核心基本功。

新手最常见错误：用模糊的一句话让 AI 写代码，结果完全不符合预期。

### 万能 Prompt 模板

```
【角色定位】：你是一名资深的 XX 开发工程师，拥有大量的 XX 领域的开发经验，代码规范、注释完整、兼容性强
【需求背景】：我需要做一个 XX 项目，用于 XX 场景，解决 XX 问题
【核心目标】：1. XX 2. XX
【输出规范】：1. 代码使用 XX 语言/框架，版本为 XX 2. 代码必须添加完整的中文注释 3. 按模块拆分代码，标注每个文件的名称和作用 4. 提供完整的运行步骤和依赖安装说明
【约束条件】：1. 不得使用 XX 不兼容的依赖包 2. 必须适配 XX 环境 3. 代码必须可直接运行，无缺失内容 4. 不得出现安全漏洞
【验收标准】：实现 XX 功能，满足 XX 要求，可通过 XX 方式验证。
```

### 好的提示词 vs 差的提示词

差的提示词：模糊的一句话，无结构，无约束
好的提示词（以贪吃蛇游戏为例）：包含角色定位（前端游戏开发工程师）、需求背景（编程实践和效果演示）、核心目标（核心玩法+UI）、输出规范（HTML5 Canvas/CSS3/JS，中文注释，完整代码）、约束条件（无复杂依赖，适配主流浏览器）、验收标准（双击打开可试玩）

结果对比：好的提示词产出的界面更炫酷、功能更完整、有开始和结束界面。

## 第三节：提示词核心技巧总结

### 四大核心技巧

（1）**需求要具体**：不要说"帮我弄个好看的网页"，要说"帮我写一个适合在手机上看的网页，风格极简，主色调蓝色，从上到下分为四个模块：顶部导航条、轮播图、内容列表和底部版权信息"。具体到这个程度，AI 才不会自由发挥跑偏。

（2）**告诉 AI 绝对不能干什么**：设定清晰边界。如"绝对不能使用冷门的第三方插件，必须保证代码没有安全漏洞"。丑话说在前面，把雷区提前排掉。

（3）**输出规范要明确**：指定语言、框架版本、注释语言、文件拆分方式。

（4）**验收标准要可验证**：能用什么方式验证功能完成。

## 第七节：项目实战（上）— 3D 地球花园

### 项目概述
基于 Web 端的 3D 数据可视化应用。通过可自由旋转缩放的 3D 地球展示世界各地代表性植物模型。

### 技术栈
- 前端框架：Next.js + React
- 3D 引擎：Three.js + React Three Fiber (R3F)
- 样式方案：Tailwind CSS
- 动画库：Framer Motion + GSAP

### 开发阶段
- Phase 1: 基础环境搭建与数字地球点亮（初始化项目、建立 3D 场景、渲染地球、OrbitControls）
- Phase 2: 数据结构定义与模型种植（定义 JSON、经纬度→笛卡尔坐标转换、加载 .glb 植物模型）
- Phase 3: 镜头运镜与基础 3D 交互（Hover 放大/发光、Click 相机平滑飞行对焦）
- Phase 4: UI 覆盖层与数据联动控制台（统计区、信息浮窗、毛玻璃控制台、数据筛选联动）

### 开发方式
每完成一个 Phase 后人工检查确认，再让 AI 继续下一步。

## 第九节：作弊小抄 — Vibe Coding 前的 Checklist

### （1）选择主流技术栈
- 基础网站：Wix、Framer、BlackBoxAI 等网站构建器
- Web 应用：Next.js + Supabase（最大用户基数、最多示例、AI 最擅长）
- 后端业务逻辑：加 Python
- 游戏：Unity 或 Unreal（不要用 JS 氛围编程做游戏）
- 核心原则：选择 AI 最熟悉的技术栈，否则会浪费数天修复本可几秒解决的 bug

### （2）写一个简单的 PRD
- PRD 只需做两件事：澄清真正想要什么 + 拆分成小步骤
- 一次只给 AI 一个步骤，不要说"一次性全部做完"
- 工作流：聊天1 实现步骤1 → 测试修复 → 新聊天 实现步骤2 → ...

### （3）使用版本控制
- AI 大概率会搞坏代码，需要回滚方式
- 推荐 Git，手动提交能迫使追踪进度

### （4）提供可工作的代码样例
- 在构建完整功能前，先写小型可工作脚本验证核心功能
- 验证通过后保存，作为后续对话的参考传给 AI
- 避免在细微不匹配上浪费数小时

### （5）卡住时，用更好信息重开新聊天
- "复制错误→粘贴修复→新错误→重复"是陷阱
- 打开全新聊天，告诉 AI：哪里坏了 / 希望怎么做 / 已经尝试过什么 / 附上日志、错误信息、截图
- 聊天历史越长，AI 越笨。干净上下文 + 清晰输入能解决无限重试解决不了的问题
